# 「贴语录」完整手动配置

目标：运行后选择「我说 / 她说」，再选择「仅剪贴板文字 / 仅录音 / 文字+录音」，最后只创建一条语录。

本文对应仓库里的 `/api/quick` 实现（`src/app/api/quick/route.ts` + `src/lib/quickCapture.ts`）。服务端这三种上传方式已由自动化测试覆盖，跑 `node scripts/test-quick.mjs` 可复验；线上要等这次改动部署后才生效。快捷指令 App 里的流程需要照本文手动搭一遍。

## 0. 当前状态与准备

服务端：三种方式都能落库，每次只新增一条语录。

| 方式 | 请求体 | 服务端行为 |
| --- | --- | --- |
| 仅剪贴板文字 | JSON | 建一条 `quote`，无媒体 |
| 仅录音 | 表单 | 建一条 `quote`，正文为空，挂一段 `audio` |
| 文字+录音 | 表单 | 建一条 `quote`，正文和录音在同一条里 |

录音的时长由服务端用 ffmpeg 读出来写进库，语录墙的气泡不用先播一次就能显示时长。表单里的录音即使没有文件名、`Content-Type` 缺失或是 `application/octet-stream`，服务端也会按文件头魔数认出它是音频；认不出来时才退回用字段名 `audio` 兜底，所以字段名要保持 `audio`。

快捷指令 App：之前的自动编辑中断了，当前那条不能当成完成版运行，需要按下文重建。

- 原来的「获取 URL 内容」上传动作已被移除，需要按下文重建。
- 说话人列表误多了一项「文字+录音」；说话人列表只能有「她说」「我说」两项。
- 三选一菜单和两个录音动作已经插入，但分支、变量和上传尚未完整连接。
- 原来的无条件「已贴上语录墙」通知不能继续放在流程中间，改用最后的结果判断。

建议先复制一份当前快捷指令作为编辑备份，再按下面的完整顺序调整工作版本。不要保留一套旧流程和一套新流程同时执行。

准备好鉴权令牌：

- 可以从仍能正常使用的「记手帐」或「存相册」的请求头中找到现有令牌。
- 也可以由你从服务器的 `SHORTCUT_TOKEN` 配置中取得。
- 本文不写出真实令牌，也不要把真实令牌发到聊天里。

## 1. 变量约定

下文 `[变量名]` 表示在快捷指令里插入的变量令牌，不是手工输入的一段文字。不要把方括号一起输入。

| 变量名 | 类型 | 来源 |
| --- | --- | --- |
| `说话人` | 文本 | A02「从列表中选取」的所选项目 |
| `正文` | 文本 | 对应分支中从剪贴板提取出的文本 |
| `录音文件` | 文件 / 音频媒体 | 对应分支的「录音」输出 |
| `网络结果` | 字典 / URL 内容 | E01「结束菜单」输出的菜单结果 |
| `错误信息` | 文本 | 从网络结果读取的 `error` 字段 |

所有「设定变量」节点都要手动核对输入来源，不能仅因为动作相邻就假定正确。

### 插入变量

- iPhone：点字段，使用变量选择器选择对应变量或动作输出。
- Mac：在文本字段编辑状态右键，选择「插入变量」，再选择变量；必要时选「选择变量」定位来源动作。
- 文件字段：先把类型设为「文件」，再用值选择器选择录音输出或 `录音文件`。

## 2. 完整结构

```text
A01 列表：她说、我说
A02 从列表中选取：这句话是谁说的？
A03 设定变量：说话人
A04 从菜单中选取：这次想怎么贴语录？
    仅剪贴板文字
        B01 获取剪贴板
        B02 从输入中获取文本
        B03 设定变量：正文
        B04 如果正文没有任何值
            B05 显示提醒
            B06 停止并输出
        B07 结束如果
        B08 获取 URL 内容：POST JSON
    仅录音
        C01 录音
        C02 设定变量：录音文件
        C03 如果录音文件没有任何值
            C04 显示提醒
            C05 停止并输出
        C06 结束如果
        C07 获取 URL 内容：POST 表单
    文字+录音
        D01 获取剪贴板
        D02 从输入中获取文本
        D03 设定变量：正文
        D04 如果正文没有任何值
            D05 显示提醒
            D06 停止并输出
        D07 结束如果
        D08 录音
        D09 设定变量：录音文件
        D10 如果录音文件没有任何值
            D11 显示提醒
            D12 停止并输出
        D13 结束如果
        D14 获取 URL 内容：POST 表单
E01 结束菜单
E02 设定变量：网络结果
E03 获取字典值：ok
E04 如果 ok 有任何值
    E05 显示通知：已贴上语录墙
E06 否则
    E07 获取字典值：error
    E08 设定变量：错误信息
    E09 显示通知：上传失败
E10 结束如果
```

三个分支是互斥的，每次只运行其中一个。不要使用「重复每一项」，不要把三条上传请求放在菜单外顺序执行。

## 3. 前置节点 A

### A01：列表

操作名称：`列表`。

只保留两项，顺序如下：

| 项目 | 类型 | 值 |
| --- | --- | --- |
| 1 | 文本 | `她说` |
| 2 | 文本 | `我说` |

不要在这个列表里加入「仅录音」「文字+录音」等上传模式。

### A02：从列表中选取

操作名称：`从列表中选取`。

| 设置 | 值 |
| --- | --- |
| 输入 | A01 的 `列表` 输出 |
| 提示 | `这句话是谁说的？` |
| 选择多个 | 关闭 |

### A03：设定变量

操作名称：`设定变量`。

| 设置 | 值 |
| --- | --- |
| 变量名称 | `说话人` |
| 输入 | A02 的 `所选项目` |

### A04：从菜单中选取

操作名称：`从菜单中选取`，不是再添加一个「从列表中选取」。

| 设置 | 值 |
| --- | --- |
| 提示 | `这次想怎么贴语录？` |
| 选项 1 | `仅剪贴板文字` |
| 选项 2 | `仅录音` |
| 选项 3 | `文字+录音` |

添加后，系统会自动生成三条分支标题和一个「结束菜单」。

后面的 B、C、D 节点必须分别放入对应分支，E02 以后的节点放在「结束菜单」之后。

## 4. 「仅剪贴板文字」分支 B

| 编号 | 操作名称 | 完整配置 |
| --- | --- | --- |
| B01 | 获取剪贴板 | 无额外参数；读取本次运行时的剪贴板 |
| B02 | 从输入中获取文本 | 输入明确选择 B01 的 `剪贴板` 输出 |
| B03 | 设定变量 | 名称 `正文`；输入为 B02 的 `文本` 输出 |
| B04 | 如果 | 输入 `[正文]`；条件 `没有任何值` |
| B05 | 显示提醒 | 标题 `剪贴板没有文字`；正文 `请先复制要记录的文字，再运行贴语录。`；放在 B04 内部 |
| B06 | 停止并输出 | 放在 B05 后；不指定输出内容，不选择任何变量；用于终止整条快捷指令 |
| B07 | 结束如果 | 结束 B04 |
| B08 | 获取 URL 内容 | 放在 B07 后；按下面的 JSON 请求配置 |

若系统版本显示「停止此快捷指令」，可用它代替 B06，目的仍是停止整条快捷指令，而不是仅退出菜单分支。

### B08 请求配置

| 设置 | 值 |
| --- | --- |

| 方法 | `POST` |

| 编号 | 操作名称 | 完整配置 |
| --- | --- | --- |
| E01 | 结束菜单 | 系统自动生成；结束 A04 的三个分支，不是手工输入文本 |
| E02 | 设定变量 | 名称 `网络结果`；输入明确选择 A04/E01 的 `菜单结果`，不是某条固定分支的 URL 内容 |
| E03 | 获取字典值 | 字典 `[网络结果]`；键 `ok`；获取 `值` |
| E04 | 如果 | 输入 E03 的 `字典值`；条件 `有任何值` |
| E05 | 显示通知 | 内容 `已贴上语录墙`；标题 `贴语录`；声音关闭；放在 E04 的成功分支 |
| E06 | 否则 | E04 自带的否则分支 |
| E07 | 获取字典值 | 字典重新明确选 `[网络结果]`；键 `error`；获取 `值` |
| E08 | 设定变量 | 名称 `错误信息`；输入 E07 的 `字典值` |
| E09 | 显示通知 | 标题 `贴语录失败`；正文按下方内容配置；声音关闭；放在否则内部 |
| E10 | 结束如果 | 结束 E04；整条快捷指令完成 |

E09 正文：

```text
上传未成功，请检查网络或接口配置。
[错误信息]
```

其中 `[错误信息]` 要插入变量，不能直接输入变量名。

当前本地接口成功返回 `ok: true`，错误返回 `error` 且不带 `ok`，所以上述「有任何值」判断匹配现有返回约定。它不是通用的布尔真值判断；将来若接口改为错误时返回 `ok: false`，这里也必须改成明确的布尔真值判断。

如果网络或 HTTP 错误导致「获取 URL 内容」动作直接中止，后面的通知可能不会执行，以系统错误提示为准。该情况不会执行成功通知。

## 8. 上传配置共同注意事项

- 三个请求都使用同一个 URL、同一个 `Authorization` 令牌，方法都是 POST。
- 不要手动添加 `Content-Type`。让「获取 URL 内容」按 JSON / 表单设置生成。
- 录音字段名固定用 `audio`。服务端在文件名和 `Content-Type` 都不可信时会用它兜底判断类型。
- `type` 固定为小写 `quote`，不要填 `audio` 或 `photo`。
- `audio` 字段的类型必须是「文件」。录音文件不能作为 JSON 字符串上传。
- 不要额外添加一条无条件上传动作。
- 不要保留菜单前、中间或菜单后的旧成功通知；成功通知只放在 E05。
- 不需要在最开头额外「获取剪贴板」；只有 B01 和 D01 读取剪贴板，纯录音模式不会读取。
- 本版不做语音转文字。文字+录音中的文字来自剪贴板，不是录音识别结果。
- 不额外传 `date`，语录日期继续使用服务器默认的今天。
- 取消说话人选择、上传方式选择或录音时，不要继续手动触发后面的上传节点。
- 当前接口没有请求级去重。网络报错后先确认语录墙是否已经新增，再决定是否重试。

## 9. 手动验收

先核对节点和字段，再由你使用愿意实际保存的内容运行：

| 场景 | 预期 |
| --- | --- |
| 仅剪贴板文字 + 她说 | 只新增一条文字语录，署名她说，没有录音气泡 |
| 仅剪贴板文字 + 我说 | 只新增一条文字语录，署名我说，没有录音气泡 |
| 仅录音 | 只新增一条语音语录，署名按选择，剪贴板中的文字不出现 |
| 文字+录音 | 只新增一条语录，文字、录音气泡和署名在同一条中 |
| 空剪贴板 + 仅文字 | 提醒后停止，不上传 |
| 空剪贴板 + 文字+录音 | 提醒后停止，不开始录音、不上传 |
| 取消选择或录音 | 不新增语录 |

语录墙目前只展示每条语录的第一份音频，本配置每次只上传一段录音。

服务端会从录音里读出时长并存库，气泡直接显示；万一某段读不出来（服务器没装 ffmpeg 或格式解析失败），气泡会退回成播放时现读元数据，不影响播放。不要把网页录音组件的 5 分钟计时限制误认为快捷指令接口也会自动执行同样的限制——接口只限制总大小 500MB。

纯录音那条语录正文是空的，便利贴上只有语音气泡，这是预期效果，不是上传丢了文字。
