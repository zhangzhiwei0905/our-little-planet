# iPhone 多选手帐与纯相册上传

如果遇到“Live Photo 上传后只有静态图”，请优先使用 [完整调试版配置](iphone-shortcuts-debug.md)。
调试版明确规定变量类型、计数判断、日志位置，并核对 ZIP 内实际文件；默认不上传。

## 上线前提

本文对应支持 `type=photo` 和 ZIP 的新版 `POST /api/quick`。先部署新版接口，再运行这些指令。
URL、`Authorization: Bearer ...` 沿用已经成功的单张实况上传指令，不需要重新登录作者后台。
不要手动添加 `Content-Type`，由「获取 URL 内容」根据表单自动设置。

建议复制当前已跑通的快捷指令，保留一份单张测试版。另做两份：

| 快捷指令名称 | type | 行为 |
| --- | --- | --- |
| 写一篇手帐 | `journal` | 一次多选并上传，创建一篇手帐 |
| 存进相册 | `photo` | 一次多选并上传，只创建相册内容 |

两份共用下面的媒体整理动作，区别仅是正文输入和表单字段。
普通视频原样上传；静态图和实况的静态部分转为 JPEG。
实况的动态部分使用你手机上已经测试成功的「编码媒体」配置。

## 一、选择媒体

1. 在「选择照片」中开启「选择多张」，不要设置成只允许静态图片的筛选条件。
2. 将选择结果设为变量 `所选媒体`。
3. 添加「计数」，输入 `所选媒体`。
4. 如果数量为 0，停止；如果大于 9，显示提醒并停止。服务器也会校验数量。
5. 添加「重复每一项」，输入 `所选媒体`。下面的处理动作都放在循环内部。

一些 iOS 中文版本的动作叫「选取照片」「筛选照片」「过滤图像」或「制作归档」，
名称可能略有区别。筛选条件中需要使用的是「媒体类型」和「照片类型」。
这些混选筛选设置还需要在你的 iPhone 上验证；找不到条件时先发配置截图，
不要用「所有照片都编码成视频」代替实况判断。

## 二、循环内部：每项单独处理

先做两个动作：

1. 「设定变量」：`原媒体` = 当前的 `重复项目`。
2. 「文本」：填 `item-`，后面插入蓝色变量 `重复索引`；设为变量 `配对名`。

得到的名称是 `item-1`、`item-2`、`item-3`，不要继续对全部媒体使用 `live-test`。
最多 9 项，不需要给索引补零。
名称内只放基底，不手填 `.jpg`、`.mov`；设置名称时保留自动添加扩展名的默认配置。

### 先判断普通视频

添加「筛选照片 / 过滤图像」：

- 输入明确指定 `原媒体`，不是整份相册或上一个动作的文本。
- 条件为「媒体类型是视频」。
- 不排序、不改变原媒体。

添加「如果」，条件为筛选结果「有任何值」。

视频分支：

1. 对 `原媒体` 使用「设置名称」，名称设为 `配对名`。
2. 用「添加到变量」将重命名的文件加入变量 `上传文件`。
3. 不做 JPEG 转换，不重新编码普通视频。

### 否则，判断 Live Photo

在视频判断的「否则」内部，再添加「筛选照片 / 过滤图像」：

- 输入仍明确指定 `原媒体`。
- 条件为「照片类型是实况照片 / Live Photo」。

添加第二个「如果」，条件同样为筛选结果「有任何值」。

实况分支：

1. 「转换图像」：输入 `原媒体`，格式 JPEG。
2. 「设置名称」：输入转换后的图像，名称 `配对名`。
3. 「添加到变量」：将重命名后的图片加入 `上传文件`。
4. 「编码媒体」：输入重新选回 `原媒体`，关闭「仅音频」，使用已经跑通的配置。
5. 「设置名称」：输入编码后的媒体，名称还是 `配对名`。
6. 「添加到变量」：将重命名后的视频也加入 `上传文件`。

这一项会产生例如 `item-2.jpg` 和 `item-2.m4v` 两个文件；服务器会配成一张实况。
视频扩展名由系统实际输出决定，不要强行改成 MOV。

第二个判断的「否则」是静态照片分支：

1. 「转换图像」：输入 `原媒体`，格式 JPEG。
2. 「设置名称」：输入转换后的图像，名称 `配对名`。
3. 「添加到变量」：将重命名后的图片加入 `上传文件`。

关闭两个「如果」，然后结束「重复每一项」。
`上传文件` 是「添加到变量」逐个累积的文件列表，不要在循环中用「设定变量」反复覆盖它。
同样不要用普通文本保存这个列表，否则文件会丢失类型。

## 三、循环结束后：只上传一次

1. 添加「制作归档 / 制作压缩文件」，输入明确选变量 `上传文件`，格式 ZIP。
2. 将归档设为变量 `媒体包`。必要时设置名称为 `media`，保留 `.zip` 扩展名。
3. 添加 URL，沿用原来的完整 `/api/quick` 地址。
4. 添加「获取 URL 内容」：方法 POST；请求头沿用令牌；请求体选择「表单」。
5. 最后可用「快速查看」检查返回结果。收到 `ok: true` 后不要再重复运行同一批。

「记手帐」的结果提示使用以下判断：

1. 从 `URL 的内容` 中获取字典键 `error` 的值。
2. 如果该字典值「没有任何值」，读取 `mediaCount` 并显示成功通知。
3. 否则显示「上传失败：」和前面获取的 `error` 字典值，并提醒压缩视频或分批上传。

文件总量上限为 500 MiB（界面简称 500MB），ZIP 解包后的总量也不能超过该限制。
Nginx 配置见 `deploy/nginx.conf.example`：请求体允许 501 MiB，其中 1 MiB
只用于 multipart 表单包装，应用仍严格检查 500 MiB 文件上限。
超大请求及 Nginx 网关异常返回 JSON，不能返回 HTML 错误页给字典读取动作。
超时可能发生在保存完成之后，重试前先到手帐页面确认，避免重复提交。
该配置和 `scripts/apply-upload-limit.sh` 同步到服务器后，运行
`DOMAIN=你的域名 bash scripts/apply-upload-limit.sh`：脚本会备份现有配置，
通过 `nginx -t` 后平滑重载，安装、检查或重载失败时恢复原配置。

不要把上传动作放进「重复每一项」里，那会为每一项分别创建条目。
也不要直接对原始 Live Photo 列表打包；必须先整理出照片和视频两部分。

整理后的 ZIP 示例：

```text
item-1.jpg       静态照片
item-2.jpg       实况静态部分
item-2.m4v       同一张实况的动态部分
item-3.mp4       普通视频
```

服务器会把这些文件显示为 3 项媒体，而不是 4 项。

## 四、两条指令的不同设置

### 写一篇手帐

在选择媒体前添加「询问输入」，提示「写点今天的事」，类型文本，结果设为变量 `正文`。
标题可以暂不添加，后续需要时再加一项输入。
即使正文空白，只要有媒体也能创建一篇手帐。

表单字段：

| 字段 | 字段类型 | 内容 |
| --- | --- | --- |
| `type` | 文本 | `journal` |
| `text` | 文本 | 变量 `正文` |
| `media` | 文件 | 变量 `媒体包` |
| `title` | 文本 | 可选标题；不需要就不添加 |
| `date` | 文本 | 可选 `yyyy-MM-dd` 格式日期；不添加则服务器使用今天 |

`media` 必须是文件字段，不能将 ZIP 转成文本或 Base64 后放入 JSON。
成功结果为 `path: "/journal"`，混选三项的测试预期是 `mediaCount: 3`。
日期是整篇手帐的日期，不能从混选的每张照片分别生成多篇。

### 存进相册

复制已经做好、验证成功的批量手帐指令：

1. 改名为「存进相册」。
2. 删除询问正文和标题的动作。
3. 将表单 `type` 改为 `photo`。
4. 删除 `text`、`title` 字段，其余媒体整理和 ZIP 上传动作保持不变。

成功结果为 `path: "/album"`，这次不创建手帐条目。
后续需要一句相册备注时，再增加可选的 `text` 字段。
一批媒体会作为一组相册内容记录，日期默认今天；本版不自动提取每项的拍摄日期，
老照片可传明确的 `date`，不同日期的素材可分批上传或在后台修改。

## 五、验收与限制

先只选 1 张静态照片 + 1 张 Live Photo + 1 个短视频：

- 手帐版：只新增一篇，三个媒体都在，实况带 LIVE 标记并能播放。
- 相册版：相册新增三个媒体，手帐列表没有新增页。
- 原来的单张实况上传和纯文字语录仍能正常使用。

一次最多 9 项媒体；一个实况算 1 项，但包含 2 个实际文件。
multipart 表单单个请求的附件总量上限是 **150MB**（表单要整包读进服务器内存）；
解包后的总媒体大小不能超过 500MB。
单个大视频请走[三步直传](iphone-shortcuts-bigvideo.md)：prepare 拿地址 → 手机直传 → 登记，
文件不经过服务器内存，几百 MB 也不会拖垮小服务器。
还受线上反向代理大小限制、请求超时、手机网络及可用内存影响。
第一版优先用于照片和短视频，不保证锁屏后台长时间上传，也没有断点续传。

ZIP 不接受嵌套 ZIP / livp，不接受文字文件或其他非媒体文件；Mac 的隐藏元数据会忽略。
请求失败时显示错误，检查网站有没有已经收到这批媒体再重试，避免重复入库。
实况转换用于网站回放，并非苹果原始 Live Photo 的无损归档。

开发环境需安装依赖，并提供带 libx264 的 ffmpeg：

```bash
node --test scripts/test-quick.mjs
npx tsc --noEmit
npx eslint src/lib/quick-files.ts src/lib/quickCapture.ts src/app/api/quick/route.ts scripts/test-quick.mjs
```

测试在系统临时目录创建数据库和生成媒体，不向生产 OSS 上传，不改动真实手帐数据。
